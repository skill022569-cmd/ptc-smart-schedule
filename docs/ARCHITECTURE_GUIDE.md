# PTC Smart Schedule — คู่มือสถาปัตยกรรมและอัลกอริทึม

ระบบจัดตารางเรียน-ตารางสอนอัตโนมัติ วิทยาลัยการอาชีพโพนทอง (เอกสารสำหรับกรรมการตรวจประเมิน)

## 1. ภาพรวมสถาปัตยกรรม

```
เบราว์เซอร์ (React / Next.js App Router + Tailwind)
   │  หน้า: ภาพรวม · จัดการ/รันตาราง · ตาราง (ครู/ห้อง/กลุ่ม/นักเรียน/วิชา) · ทำเนียบ · แจ้งปัญหา · PDPA
   │  Widget: ผู้ช่วย AI (มุมขวาล่าง) · แบนเนอร์ขอความยินยอม PDPA
   ▼
Next.js Route Handlers (Node.js runtime)
   /api/generate      → Scheduling Engine (CSP + GA) → บันทึกผล
   /api/resolve       → Conflict Analyzer: แบ่งคาบ / สลับคาบ / จัดเอง
   /api/export        → Excel (exceljs) แยก Sheet; PDF = หน้า /schedule/print + พิมพ์จากเบราว์เซอร์
   /api/backup        → Snapshot JSON / Restore
   /api/ai-assistant  → Claude API (ใส่บริบทตารางของผู้ถามลงใน prompt)
   /api/pdpa, /api/issues, /api/auth/*
   ▼
Prisma ORM ──► TiDB Serverless (MySQL-compatible, Automated Backup + PITR)
```

| ส่วน | ไฟล์ |
|---|---|
| Schema ฐานข้อมูล | `prisma/schema.prisma` |
| Engine (TypeScript ล้วน ไม่ผูกฐานข้อมูล) | `src/engine/*` |
| แปลงข้อมูล DB ↔ Engine | `src/lib/engine-io.ts` |
| ข้อมูลจำลอง / stress test | `prisma/data.ts`, `prisma/seed.ts`, `scripts/stress.ts` |

## 2. โครงสร้างข้อมูลที่สำคัญ

- `schedules` เก็บ **1 แถวต่อ 1 คาบ** (เชื่อม enrollment–ห้อง–คาบ) แถวที่ `slotId = NULL, status = CONFLICT` คือรายการที่จัดไม่สำเร็จพร้อม `conflict_reason`
- `enrollments` ลงได้ทั้ง **ทั้งกลุ่ม** (`group_id`) หรือ **รายบุคคล** (`student_id`) เช่น นักเรียนคู่ขนานที่ไปเรียนวิชาสามัญกับกลุ่มอื่น; `allow_split` = อนุญาตแบ่งคาบ
- `student_groups.study_days` = วันที่มาเรียนที่วิทยาลัย (กลุ่มทวิภาคีเช่น `[1,2,3]` = จันทร์–พุธ)
- `teachers_constraints.unavailable_slots` = JSON `[{day, period}]` เวลาที่ติดประชุม/ลา

## 3. Pipeline การจัดตาราง

### 3.1 Pre-check (`validator.ts → precheck`)
ตรวจก่อนคำนวณ: ชั่วโมงสอนรวมของครูเกิน `max_hours_per_week`, วิชาที่ไม่มีห้องประเภท/ความจุที่ใช้ได้, กลุ่มที่ชั่วโมงเรียนเกินจำนวนคาบในวันที่มาเรียน — แสดงเป็นคำเตือนในหน้าแอดมิน

### 3.2 แบบจำลองปัญหา (`model.ts`)
- **ตัวแปร** = "ก้อนคาบ" (session) ของแต่ละ enrollment: วิชา 3 คาบที่ไม่อนุญาตแบ่ง = 1 ก้อนยาว 3 คาบ (soft constraint "เรียนต่อเนื่อง" ถูกบังคับด้วยรูปแบบตัวแปรเลย); ถ้าอนุญาตแบ่ง = ก้อนละ ≤2 คาบ
- **โดเมน** = (วัน, คาบเริ่ม, ห้อง) ที่ก้อนวางได้โดยไม่คร่อมพักเที่ยง และอยู่ในวันที่กลุ่มมาเรียน
- **การตรวจชนแบบ O(1)** ด้วยตาราง occupancy `"วัน-คาบ|ทรัพยากร"`:
  - `T{ครู}` ครูหนึ่งคนสอนได้ที่เดียว · `R{ห้อง}` ห้องหนึ่งห้องเรียนได้วิชาเดียว
  - `G{กลุ่ม}` วิชาที่เรียนทั้งกลุ่ม · `S{นักเรียน}` วิชาที่ลงรายบุคคล · `GI{กลุ่ม}` "มีนักเรียนของกลุ่มนี้เรียนรายบุคคลอยู่"
  - วิชาทั้งกลุ่มต้องไม่ชนทั้ง `G` และ `GI` ของกลุ่มตัวเอง; วิชารายบุคคลต้องไม่ชน `S` ของตัวเองและ `G` ของกลุ่มบ้าน → **นักเรียนคู่ขนานที่ลงข้ามกลุ่มจะไม่มีคาบซ้อน** แต่ 2 คนในกลุ่มเดียวกันที่ลงรายบุคคลคนละวิชาเรียนพร้อมกันได้

### 3.3 Hard constraints (ห้ามละเมิด)
ครูไม่สอน 2 ที่พร้อมกัน · ห้องไม่ซ้อน · กลุ่ม/นักเรียน (รวมคู่ขนาน) ไม่ซ้อน · ไม่ลงเวลาที่ครูไม่สะดวก · ไม่ลงพักเที่ยง · ห้องตรงประเภทและจุพอ · เรียนเฉพาะวันที่กลุ่มมาวิทยาลัย

### 3.4 Soft constraints (`softPenalty`)
| เงื่อนไข | โทษ |
|---|---|
| คาบว่างคั่นกลางวันของนักเรียน | 3 / คาบ |
| คาบว่างคั่นกลางวันของครู | 2 / คาบ |
| สอนคาบเย็น (คาบ 10) | 2 / คาบ |
| ขัดช่วงเวลาที่ครูต้องการ (เช้า/บ่าย) | 1 / คาบ |
| วิชาเดียวกันมีหลายก้อนในวันเดียว | 4 / ก้อน |

### 3.5 CSP (`csp-solver.ts`)
1. เรียงตัวแปรแบบ **MRV** (Minimum Remaining Values): ก้อนที่มีตำแหน่งเป็นไปได้น้อยที่สุด (ครูติดเยอะ/ห้องเฉพาะทาง/ก้อนยาว) วางก่อน
2. วางตำแหน่งแรกที่ผ่าน hard constraints (forward check ผ่าน occupancy)
3. ถ้าวางไม่ได้ → **ejection repair**: หาตำแหน่งที่มี "ผู้ขวาง" เพียง 1 ก้อน แล้วลองย้ายผู้ขวางไปที่อื่น

### 3.6 Genetic Algorithm (`genetic-opt.ts`)
- ประชากรเริ่มต้น = ผล CSP หลายชุด (สุ่มลำดับตัวแปรที่ยากเท่ากันต่างกัน)
- Fitness = `1000 × คาบที่ยังจัดไม่ได้ + soft penalty`
- แต่ละรุ่น: คัดครึ่งที่ดีที่สุด (elitism, μ+λ) → กลายพันธุ์ด้วยการย้าย 1–5 ก้อนไปตำแหน่งอื่นที่ **ยังผ่าน hard constraints** และลองวางก้อนที่ค้างใหม่
- ไม่ใช้ crossover เพราะการผสมตาราง 2 ชุดมักทำให้เกิดคาบชน; ทุกตัวในประชากรจึงไม่มีตารางชนตลอดเวลา
- หยุดเมื่อครบจำนวนรุ่นหรือหมดเวลา (ค่าเริ่มต้น 15 วินาที) แล้ว **validate ซ้ำทั้งตารางตั้งแต่ต้น** ก่อนบันทึก

## 4. การวิเคราะห์ตารางชนและแนวทางแก้ (`conflict-analyzer.ts`)

สำหรับทุกวิชาที่ยังจัดไม่ครบ ระบบสร้างตารางสถานะรายคาบ (ครูว่าง? กลุ่มว่าง? มีห้องว่าง?) แล้วหาช่วงที่ว่างตรงกันในแต่ละวันเพื่ออธิบายว่า **ทำไมต่อไม่ถึง N คาบ** และคาบรอบๆ ติดอะไร

**กรณีศึกษาครูสมศรี** (สร้างไว้ใน seed เสมอ): วิชาปฏิบัติ 3 คาบรวด ครูว่างเฉพาะ จ. คาบ 3, 4, 6 และ อ. คาบ 7 — ผลจริงจากระบบ:

> **[จัดตารางไม่สำเร็จ - คาบต่อเนื่องไม่เพียงพอ / คาบชน]**
> วันจันทร์ ว่างตรงกันเพียง คาบ 3-4 (ต่อเนื่องสูงสุด 2 คาบ) ไม่พอสำหรับ 3 คาบติดต่อกัน และคาบ 2 ครูสมศรี ใจดี ไม่สะดวกสอน, คาบ 5 เป็นพักกลางวัน, คาบ 6 กลุ่มเรียน ปวส.1/1 คอมพิวเตอร์ธุรกิจ มีเรียนวิชา 30204-2102 สัมมนาวิชาชีพ อยู่แล้ว

แนวทางแก้ 3 ปุ่ม (คำนวณล่วงหน้าแล้ว กดแล้วบันทึกทันที):
1. **แบ่งคาบ (Split)** — ตั้ง `allow_split` แล้ววาง 2+1 คาบ โดยเลือกวันต่างกันก่อน (ตัวอย่าง: จ. 3-4 + อ. 7)
2. **สลับอัตโนมัติ (Swap)** — หาตำแหน่งที่มีวิชาอื่นขวางอยู่ 1 รายการ และวิชานั้นย้ายไปช่องอื่นได้ → ย้ายแล้ววางวิชาที่ค้าง (กรณีครูสมศรีไม่มี เพราะติดเวลาไม่สะดวกของครูเอง ซึ่งย้ายใครก็แก้ไม่ได้ ระบบจึงปิดปุ่มนี้)
3. **จัดเอง (Manual Override)** — ตารางไฮไลต์ เขียวเข้ม = ครูและนักเรียนว่าง, เขียวอ่อน = ครูว่าง, เหลือง = นักเรียนว่าง คลิกคาบเริ่มต้นเพื่อวาง (ระบบตรวจ hard constraints ก่อนบันทึก และบอกเหตุผลถ้าวางไม่ได้)

## 5. Stress Test

```bash
npm run stress                      # engine ล้วน ไม่ต้องมีฐานข้อมูล
SEED_SCALE=stress npm run db:seed   # ลงฐานข้อมูลจริง
```
ผลที่วัดได้ (เครื่องพัฒนา, Node 22): นักเรียน 2,000 · ครู 112 · วิชา 506 · ห้อง 76 · กลุ่ม 80 · การลงทะเบียน 608 (≈1,900 คาบ/สัปดาห์)
→ ประมวลผล ~2–5 วินาที, **hard-constraint violations = 0** (ตรวจซ้ำโดย `validate` อิสระจาก solver), จัดไม่สำเร็จ 1–8 รายการขึ้นกับ seed สุ่ม (รวมกรณีครูสมศรีที่ตั้งใจสร้าง) และทุกรายการมีคำอธิบาย + ทางแก้

Unit tests: `npm test` (ตรวจการชนของครู/ห้อง/กลุ่ม/นักเรียนคู่ขนานรายบุคคล, พักเที่ยง, เวลาไม่สะดวก, Swap, กรณีครูสมศรี)

## 6. ผู้ช่วย AI
- Claude API (`claude-opus-5-5`, effort ต่ำเพื่อความเร็ว, server-side fallback เมื่อโมเดลปฏิเสธ)
- **Context injection**: ส่งตารางของผู้ถาม (ครู = ตารางสอน, นักเรียน = ตารางเรียนกลุ่ม + รายบุคคล), เวลาคาบ, วันเวลาปัจจุบัน (Asia/Bangkok) และตารางของครูที่ถูกเอ่ยชื่อในคำถาม (เช่น "ครูสมศรีว่างวันไหน")
- ระเบียบการใช้งานอยู่ใน system prompt (cache ได้) ไม่ส่งเบอร์โทร/อีเมลให้ AI

## 7. PDPA
- แบนเนอร์ขอความยินยอมจนกว่าจะกดยอมรับ → `users.pdpa_consent_at` + log ใน `pdpa_consent_logs` (IP, user agent)
- Masking: รหัสนักเรียนแสดงเป็น `670101xxx` ยกเว้นเจ้าของและแอดมิน; ทำเนียบบุคลากรปกปิดเบอร์โทร/อีเมล
- สิทธิ์เจ้าของข้อมูล: ดาวน์โหลดสำเนาข้อมูล (JSON), ถอนความยินยอม, ขอแก้ไข/ลบ (สร้างเป็นเรื่องในระบบแจ้งปัญหาให้เจ้าหน้าที่ตรวจ เพราะข้อมูลการเรียนต้องเก็บตามระเบียบ)

## 8. Backup & Restore
- **ระดับฐานข้อมูล**: TiDB Cloud Automated Backup + Point-in-Time Recovery (ตั้งค่าใน TiDB Cloud Console)
- **ระดับแอป**: ปุ่ม "สร้างจุดสำรอง" เก็บตารางทุกภาคเรียน + สถานะ allow_split เป็น JSON ใน `system_backups`; Restore แทนที่ตารางปัจจุบันใน transaction เดียว (ข้ามแถวที่อ้างข้อมูลที่ถูกลบไปแล้ว) และดาวน์โหลด JSON ได้

## 9. ความปลอดภัย
- รหัสผ่าน hash ด้วย scrypt + salt, session cookie ลงลายมือชื่อ HMAC (httpOnly, sameSite=lax, secure ใน production)
- ทุก API ตรวจสิทธิ์ตามบทบาท (ADMIN/TEACHER/STUDENT); นักเรียนดูตารางรายบุคคลได้เฉพาะของตัวเอง

## 10. ข้อจำกัดที่ทราบ / แนวทางพัฒนาต่อ
- Engine รันใน request (บล็อก ~2–15 วินาที) — ถ้าผู้ใช้พร้อมกันมากให้ย้ายไป `worker_threads` หรือคิวงาน
- CSP ซ่อมแบบย้ายผู้ขวาง 1 ชั้น ไม่ใช่ backtracking เต็มรูปแบบ
- Manual override ใช้การคลิกช่อง (ยังไม่ใช่ drag & drop) และย้ายได้เฉพาะรายการที่ยังจัดไม่ได้
- ยังไม่มีหน้า import ข้อมูลตั้งต้น (ใช้ seed / Prisma Studio)
- PDF ใช้การพิมพ์ของเบราว์เซอร์ (รองรับฟอนต์ไทยโดยไม่ต้องฝังฟอนต์ใน PDF engine)
